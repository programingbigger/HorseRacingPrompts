0.今回の検討で確定した予想構造（ユーザー確認済み）

2連複の推奨「3点」は、単純な上位3頭ボックスではなく、2軸流し方式を採用する。

軸1（本命軸）+ 相手候補2頭   → 2点
軸1とは別の軸2（抑え軸）+ 相手候補1頭 → 1点
─────────────────────────
合計 3点
◎
軸1（本命軸）
最も信頼度が高い軸馬。連対率（2着以内率）を最優先評価
○
軸1相手A（対抗）
軸1と組ませる相手その1。オッズ妙味を意識して選定
▲
軸1相手B（単穴）
軸1と組ませる相手その2。オッズ妙味を意識して選定
△
軸2（抑え軸）
軸1とは別の高信頼馬。軸1が飛んだ場合の保険
☆
軸2相手（抑え相手）
軸2と組ませる相手

3点の組み合わせ： ◎-○ ◎-▲ △-☆

これはREADME.mdの方針「2連複になりそうな組み合わせを3点ピックアップする → オッズ比率の関係から、その3点はほぼ当たる」と整合する設計である。軸馬（◎△）は的中率（連対率）を担保する役割、相手馬（○▲☆）はオッズ妙味を担保する役割、と機能を分離できるため、単純な上位3頭ボックス（3頭とも人気馬なら妙味が薄く、3頭とも人気薄なら当たらない）よりも設計思想に合致する。

未決定事項（要ユーザー判断・第7章に詳細）

  • 軸2相手（☆）は、軸1相手（○▲）と重複しない別の馬とするか、それとも同一馬を再利用してよいか
  • 抑え軸（△）の機械的な選定基準（例：単勝人気3〜5番手から連対率の高い馬を選ぶ、等）

本レポートでは「☆は○▲と重複しない別馬」をデフォルト提案として以降の設計を進める（理由：評価対象の頭数が増え分析データが厚くなる／的中カバー範囲が広がる）。運用上は keiba-tansho-picker.md の該当箇所を書き換えるだけで方針変更が可能。

1-2. 現状の3層構造とデータフロー（単勝ベース）

【前日】keiba-static-collector → Info/static/ に 馬情報・騎手・調教師・競馬場・コース別脚質傾向 をキャッシュ
【当日】keiba-dynamic-collector → 直近3R分のコーナー通過順位から「脚質傾向」「バイアス」を判定 → Info/dynamic/ に保存
【予想】keiba-tansho-picker（予想モード） → 単勝推奨3頭（◎○▲）をチャット出力 → predictions.csv に1行追記（status=結果待ち）
【結果記録】keiba-result-recorder → 単勝オッズ・着順を取得し、的中区分と回収率（的中馬オッズ×100÷300）を算出 → status=記録済み
【サマリー】keiba-summary-reporter（依頼時のみ） → 的中率・回収率・判断基準の有効性を横断集計 → records/summary.md

  4. 馬体重ベスト値等の「3着以内」基準を「2着以内」に寄せるか、両方併記するか。
  5. 少頭数レース（8頭以下）を2連複予想の対象から除外するかどうかの基準。
