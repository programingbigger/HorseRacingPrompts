# 現状分析・ネクストアクションの観点ガイド

結果記録時に記入する `analysis`（現状分析）と `next_action`（ネクストアクション）の導出手順。

---

## 現状分析（`analysis` 列）— 5観点

予想レコードの `sources`（参照情報）と `reasoning`（判断理由）を結果と突き合わせ、以下の5観点で分析する。

| # | 観点 | 具体的な問い |
|---|------|-------------|
| 1 | **的中精度** | 推奨した3頭は何着だったか？回収率は1.0を超えたか？ |
| 2 | **見逃し分析** | 実際の1着馬を予想に入れていたか？入れていなかった場合、どの情報を見ていれば拾えたか？（参照済みキャッシュ内にヒントがあったか、それとも情報自体が不足していたか） |
| 3 | **判断根拠の検証** | `reasoning` に挙げた各判断基準（距離適性・前走展開・騎手成績等）は実際に有効だったか？有効/無効/不明を基準ごとに判定する |
| 4 | **オッズ妙味の検証** | 本命のオッズは妙味があったか？低オッズ馬（3倍以下）を本命にしていた場合、それは期待値的に正しかったか？ |
| 5 | **見逃しパターン** | 荒れたレースで固い予想をしていないか？人気馬に引きずられていないか？過去レコードと同じ失敗を繰り返していないか？ |

**記入形式：** `的中精度:{...} / 見逃し:{...} / 根拠検証:{基準名=有効/無効/不明を列挙} / オッズ妙味:{...} / パターン:{...}`

該当なしの観点は `該当なし` と記す（省略しない）。

---

## ネクストアクション（`next_action` 列）— 3点セット

現状分析から導く。**必ず3点セット（観点・取得・修正）で記入する**。分析の結果、追加すべき観点がない場合は `観点:なし（現行構成で妥当） / 取得:- / 修正:-` と記す。

### 1. 観点の提案（`観点:`）

「こういう観点を入れると勝率（回収率）が上がるのではないか？」という仮説。

- 見逃し分析で「情報自体が不足していた」場合が最大のヒント
- 例：調教タイム、血統（種牡馬×馬場適性）、ラップ適性、休み明け成績、輸送距離

### 2. 観点の取得方法（`取得:`）

その観点をどこから取得できるか。具体的なURLパターンまたはデータ源を明記する。

- 例：`netkeiba調教ページ(https://race.netkeiba.com/race/oikiri.html?race_id=XXX)`
- 取得手段が不明な場合は `取得:要調査` と記す

### 3. 構成の修正箇所（`修正:`）

現在の構成のどこを修正すれば、その観点が予想フローに組み込まれるか。**ファイル名＋修正内容**まで特定する。

| 修正対象 | ファイル |
|---|---|
| 前日収集の項目追加 | `.claude/skills/keiba-static-collector/`（SKILL.md・reference/step*.md・assets/md_format.md） |
| 当日収集の項目追加 | `.claude/skills/keiba-dynamic-collector/`（同上） |
| 評価軸・重みの変更 | `.claude/agents/keiba-tansho-picker.md` の「評価軸」表 |
| 記録項目の変更 | `.claude/skills/keiba-result-recorder/assets/csv_format.md` |

- 例：`修正:keiba-static-collector step3_horse.mdに調教タイム取得を追加し、keiba-tansho-picker評価軸に「仕上がり」（中）を追加`

---

## 注意

- ネクストアクションは**提案の記録**であり、このスキル実行中に構成ファイルを勝手に修正しない（修正はユーザー＝構築者がサマリーをレビューして判断する）
- 同じ提案が過去レコードに既にある場合は「（再発）」と付記する。繰り返し出る提案はサマリーで優先度が上がる
