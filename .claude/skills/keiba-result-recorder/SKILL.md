# keiba-result-recorder

## 目的

予想時に `records/predictions.csv` へ追記された「結果待ち」レコードに対し、
①レース結果、②現状分析、③ネクストアクション（観点提案・取得方法・構成修正案）を記入し、
**1予想=1レコード** を完成させる。予想→結果検証→自己フィードバックのサイクルの中核。

---

## 入力

| トリガー例 | 動作 |
|---|---|
| 「結果を記録して {URL}」 | URLの race_id に対応するレコードを更新 |
| 「結果を記録して」「答え合わせして」（URLなし） | `status=結果待ち` のレコードを列挙し、全件を順に処理 |
| 「安田記念の振り返りして」（レース名指定） | 該当レコードを特定して処理 |

**URL形式：** `https://race.netkeiba.com/race/result.html?race_id=XXXXXXXXXXXX`（出走表URLでも可。race_id を抽出して結果ページを参照する）

---

## 前提

- **CSVの列定義・記入ルールは [assets/csv_format.md](assets/csv_format.md) に従うこと**
- `records/predictions.csv` が存在しない、または対象レコードがない場合は「対象の予想レコードがありません。先に予想モードを実行してください」と伝えて終了する（ループ禁止）

---

## 情報収集の基本方針（Chrome in Claude 優先）

```
① Chrome in Claude（mcp__claude-in-chrome__navigate 等）でブラウザ経由取得（推奨・優先）
      ↓ うまくいかない場合
② WebFetch または web 検索（過去1年フィルター）で補完を試みる
      ↓ それでも取得できない場合
③ ユーザーに結果（着順・勝ち馬・単勝オッズ）の手入力を依頼する
```

```
結果記録を開始します。
対象レコード：{date} {venue}{race_no}R {race_name}（{件数}件）
```

## 実行ステップ

### ステップ 1：対象レコードの特定

1. `records/predictions.csv` を読み込む
2. URL指定あり → race_id が一致する行を対象とする
3. URL指定なし → `status=結果待ち` の全行を対象とし、対象一覧をアナウンスする
4. 対象行の `status` が既に `記録済み` の場合は「記録済みです。上書きしますか？」と確認する

### ステップ 2：レース結果の収集

netkeiba 結果ページ（`https://race.netkeiba.com/race/result.html?race_id={record_id}`）から取得：

- 推奨3頭（◎○▲）それぞれの**着順**
- **勝ち馬**（馬番:馬名）
- **勝ち馬の単勝オッズ**（的中時は的中馬のオッズ）
- 回収率を計算：単勝3頭各100円購入想定 → `的中馬オッズ×100÷300`（不的中は0）

### ステップ 3：現状分析

レコードの `sources`（参照情報）・`reasoning`（判断理由）と結果を突き合わせ、
[reference/analysis_guide.md](reference/analysis_guide.md) の**5観点**（的中精度・見逃し分析・判断根拠の検証・オッズ妙味・見逃しパターン）で分析する。

見逃し分析では、勝ち馬のキャッシュ（`Info/static/馬情報/` 等）が存在すれば必ず読み返し、「参照済み情報内にヒントがあったか／情報自体が不足していたか」を切り分けること。

### ステップ 4：ネクストアクションの導出

[reference/analysis_guide.md](reference/analysis_guide.md) に従い、**3点セット**で記入する：

1. **観点**：勝率（回収率）を上げるために追加すべき観点の仮説
2. **取得**：その観点の取得方法（URL・データ源）
3. **修正**：現在の構成（agent / skill のどのファイル）をどう修正すればよいか

⚠️ 提案の記録のみ。このスキル実行中に構成ファイルを修正しない。

### ステップ 5：CSVの更新

- 対象行の列12〜20（結果・分析・ネクストアクション）を記入し、`status=記録済み` に更新する
- **既存行の更新**であり、新規行を追加しない
- 書式は [assets/csv_format.md](assets/csv_format.md) の記入ルール（RFC 4180・改行禁止・` / ` 区切り）に従う

### ステップ 6：振り返り結果のチャット出力

```
## 📋 結果記録：{race_name}（{date} {venue}{race_no}R）

| 予想 | 馬番・馬名 | 着順 |
|---|---|---|
| ◎ | ... | {N}着 |
| ○ | ... | {N}着 |
| ▲ | ... | {N}着 |

- **勝ち馬**：{馬番:馬名}（単勝 {オッズ}倍）
- **的中区分**：{◎的中/○的中/▲的中/不的中}
- **回収率**：{N.NN}（単勝3頭各100円想定）

### 現状分析
{5観点の要約}

### ネクストアクション
- 観点：...
- 取得：...
- 修正：...

💡 蓄積レコードの横断レビューは「サマリーを作って」で keiba-summary-reporter を実行してください。
```

---

## 注意事項

- 複数レコードを処理する場合は1件ずつステップ2〜5を完結させてから次へ進む
- 結果ページが未公開（レース未確定）の場合は「結果未確定」と伝えてその行をスキップする（`status` は変更しない）
- 取得できなかった値は `取得不可` と記載する（空欄にしない）
- 分析で得た競馬場・コースの普遍的な傾向は agent memory（keiba-tansho-picker）への記録候補として報告に含めてよい
