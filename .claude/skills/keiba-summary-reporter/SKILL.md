# keiba-summary-reporter

## 目的

`records/predictions.csv` に蓄積された予想レコードを横断集計し、
**構築者（システム開発者）がレビューしやすいサマリー** を `records/summary.md` に生成する。

サマリーが答えるべき問い：

1. 予想は当たっているか？回収率はプラスか？（予想・結果）
2. どの情報を見にいっているか？情報の取得は機能しているか？（参照情報・リンク付き）
3. どの判断基準が有効で、どれが無効か？（判断理由 → 現状分析）
4. 次に何を直せばよいか？（ネクストアクション：追加観点・取得方法・構成修正箇所）

---

## 入力

| トリガー例 | 動作 |
|---|---|
| 「サマリーを作って」「成績をまとめて」 | 全記録済みレコードを対象に生成 |
| 「東京のサマリーを作って」「今月のサマリー」など条件付き | 条件で絞り込んで生成（ファイル名は `summary.md` のまま。冒頭に絞り込み条件を明記） |

**本スキルは依頼時のみ実行する**（結果記録のたびの自動生成は行わない）。

---

## 実行ステップ

### ステップ 0：実行開始アナウンス（必須）

```
サマリーを生成します。
対象：記録済み {N}件 / 結果待ち {M}件（集計対象外）
```

### ステップ 1：レコード読み込み

- `records/predictions.csv` を読み込む
- CSVの列定義は `.claude/skills/keiba-result-recorder/assets/csv_format.md` を参照する
- `status=記録済み` の行のみ集計対象とする。記録済みが0件の場合は「集計対象のレコードがありません。先に keiba-result-recorder で結果を記録してください」と伝えて終了する
- `status=結果待ち` の行があれば、結果記録の実行を促す一文を報告に含める

### ステップ 2：集計

[assets/summary_format.md](assets/summary_format.md) の各セクションに必要な集計を行う：

1. **成績ダッシュボード**：的中率・平均/累計回収率・条件別内訳
2. **予想・結果一覧**：全レコードの時系列テーブル
3. **参照情報の傾向**：`sources` を種別ごとに集計
4. **判断基準の有効性**：`reasoning` の基準名を正規化し、`analysis` の有効/無効/不明判定とクロス集計
5. **現状分析まとめ**：繰り返しの失敗パターン・見逃しの主因
6. **ネクストアクション**：`next_action` を提案観点ごとにまとめ、出現回数順に優先度付け

### ステップ 3：summary.md の生成

- [assets/summary_format.md](assets/summary_format.md) のフォーマットに従い `records/summary.md` を**上書き**生成する

### ステップ 4：チャット出力

生成後、以下の要約をチャットに出力する：

```
✅ records/summary.md を生成しました（対象 {N}件）

- 3頭内的中率：{％} / 平均回収率：{N.NN}
- 最重要ネクストアクション：{上位1件の観点と修正箇所}
- 結果待ちレコード：{M}件（→「結果を記録して」で更新可能）
```

---

## 注意事項

- サマリーは**集計と提案の提示まで**。構成ファイル（agent / skill）の修正は行わない。修正の実施は構築者が判断する
- レコード数が少ない集計区分（1〜2件）には必ず「サンプル少」と付記し、過度な結論を出さない
- `predictions.csv` が存在しない場合は作成せず、その旨を伝えて終了する（ループ禁止）
